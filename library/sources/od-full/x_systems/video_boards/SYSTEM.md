# Video board — the system

Everything needed to understand, extend or rebuild a board. The example in
`template/example_board_data.json` uses every field below; open
`template/example_board.html` to see the result.

## 1. Files

| file | what it is | who changes it |
|---|---|---|
| `<PRODUCT>/content/_board_thumbs/board_data.json` | the board's content — source of truth | Claude |
| `<PRODUCT>/video_board.html` | generated by `tools/build_board.py` | nobody by hand |
| `<PRODUCT>/content/_board_thumbs/board_notes.txt` | Daniel's notes; the page writes it | Daniel (through the page) |
| `<PRODUCT>/content/_board_thumbs/**.webp` | thumbnails, one per png/mp4 | `_tool/make_thumbs.py` |
| `<PRODUCT>/content/lost_takes.txt` | files that are gone for good | Claude, with Daniel's knowledge |
| `<PRODUCT>/content/video_N_assets/prompts.md` | full history of every take | Claude |
| `x_systems/video_boards/template/*` | the look and behaviour of every board | Claude, then rebuild all boards |

The page loads media by relative path (`content/...`, `videos_to_post/...`), so
it works when opened straight from the product folder in Chrome.

## 2. board_data.json

UTF-8 JSON. Plain-text fields are escaped by the builder; fields whose name
ends in `_html` are inserted as HTML (use them only for `<b>`, `<i>`, `<code>`,
`<p>`, `&mdash;`-style markup). Paths are relative to the product folder.

### Top level

```json
{
 "schema": "video-board/1",
 "product": "THEXMASGLOW - CHRISTMAS PROJECTOR",   // must equal the folder name
 "brand": "TheXmasGlow",                          // title: "<brand> — Video Board"
 "key": "thexmasglow_christmas_projector",        // browser storage key; never change it
 "favicon": "data:image/svg+xml,...",             // optional, else template/favicon.txt
 "subtitle_extra": "every prompt ... checked",    // optional, appended to the summary line
 "legend": [{"color": "#E8452C", "text": "Hook — C01"}, ...],
 "source_note_html": "<b>Source of truth</b>: ...",   // optional 5th line of "How this board works"
 "layout": "lanes",                               // optional: "lanes" (default) or "columns" (§2.6)
 "panels": [ ... ],                               // §2.1
 "lanes":  [ ... ]                                // §2.2, one per video, any order (sorted by n)
}
```

`key` keeps Daniel's notes and review clicks attached to the board. It is the
product folder name in lower case with `_` for every run of other characters.
The summary under the title is computed: videos, how many are posted (lanes
whose Status starts with `Posted`), approved shots, shots waiting for review.

### 2.1 Panels (the boxes under the title)

"How this board works" is always first and is written by the builder. Then
the product's own panels, in order:

```json
{"type": "list", "title": "Frame rules — what the image rounds taught",
 "items_html": ["<b>Lesson.</b> Why it matters.", ...], "ordered": true, "wide": false}
{"type": "spec", "title": "MerryGlowUSA retail box", "kicker": "Product box · locked 12 Sep 2026",
 "image": "product_images/box_nowindow/box_nowindow_g5.png", "lead_html": "...",
 "rows_html": [["Width", "&approx; 55 cm"], ...], "rules_html": "<b>Always in the prompt:</b> ..."}
{"type": "specs", "title": "Model settings in use", "rows": [["gpt_image_2", "quality: medium", ...], ...]}
{"type": "gallery", "title": "Bra references", "lead_html": "optional line above",
 "items": [{"label": "Leopard, front", "file": "references/bra_leopard_front.png"}, ...]}
```

`gallery` shows a row of pictures (click = full size): the board thumbnail when one exists, else the
picture itself, loaded lazily (product-level `references/` and `product_images/` have no thumbnails).

A `list` with no items is skipped. `wide: true` spans both columns.

### 2.2 Lane (one video)

```json
{
 "n": 17,                                  // video number → lane id v17
 "title": "Tree fire (video 9 framing)",   // the hook, shown as the lane heading
 "caption": "Do not let a Christmas mom see this🎁🎄",   // on-screen text, read off the export
 "final": "videos_to_post/video_17.mp4",   // null until exported → "Not cut yet" tile
 "meta": [["Status", "Posted · Sep 21"], ["Hook", "..."], ["Song", "not recorded"],
          ["Runtime", "14.21 s"], ["Resolution", "2160×3840 · 30 fps"]],
 "side_note": "optional HTML under the meta table",
 "source": {"account": "@alynne.us", "views": "9.7M views", "length": "35.5 s",
            "url": "https://www.instagram.com/reel/..."},   // optional: the competitor reel a remake copies
 "groups": [ ... ]
}
```

Meta rows, in this order: **Status, Hook**, any product rows (TheXmasGlow:
Room, Projection), **Song, Runtime, Resolution**. The builder adds **Shots**
(clips · frames). Unknown values are written `not recorded`, never left out.
Status is `In production` → `Exported · Mon DD` → `Posted · Mon DD` (only when
Daniel says it is posted).

### 2.3 Group

```json
{"name": "B-roll 1", "sub": "the product", "color": "#2D6BF0", "cards": [ ... ]}
```

The count chip (`3 clips · 3 frames · approved`) is computed.

### 2.4 Card (one shot)

```json
{
 "clip": "c03",                       // shot id → data-clip; card number = 3
 "stage": "clip",                     // "frame" | "clip" | "refs" (motion transfer, before generating)
 "status": "approved",                // "review" | "approved" | "rejected"
 "title": "The projector lifted",     // short: must fit on one line
 "desc": "Hand lifts the projector out of the box",
 "tip": "optional longer hover text (defaults to desc)",
 "variant": "optional badge, e.g. REUSED FROM VIDEO 7",
 "file": "optional - the file under review; default below",
 "chip": "optional - override the status chip text",
 "frames": [{"label": "START FRAME", "file": "content/video_17_assets/starting_frames/v17_c03_g2.png"},
            {"label": "FRAME 2 · ROOM REFERENCE", "file": "content/video_17_assets/references/v17_c03_r1.png"}],
 "driver": "optional - motion transfer only: content/video_17_assets/references/v17_c01_r1.mp4",
 "looks": [{"label": "Woman", "file": "content/video_17_assets/references/v17_c01_r2.png"},
           {"label": "Room",  "file": "content/video_17_assets/references/v17_c01_r3.png"}],
                                      // optional - motion transfer only: the pictures the run recasts from
                                      // (the new person, the new place, ...); kept on the card after the clip
                                      // the driving video; then "frames" is [] and stage is "clip";
                                      // the card shows the generated clip up top AND in the clip strip
 "blocked": "optional - columns layout, stage refs: a run that was submitted but gave no clip (e.g. refused by Higgsfield as NSFW); shown in row 3 instead of 'ready to generate'",
 "tags": {"image": "gpt_image_2_5", "clip": "seedance_2_5 · 720p · 4 s"},
 "take": {                            // the clip; absent while stage is "frame"
   "file": "content/video_17_assets/clips/v17_c03_g1.mp4",   // info 1: model · resolution · duration · audio
                                                             // info 2: job <8> [· 2K <w>×<h> when upscaled]
   "play": "content/video_17_assets/clips/upscaled/v17_c03_g1.mp4",   // optional: what the player loads
   "poster": "optional - a picture to show when the clip is lost",
   "label": "Clip in the cut",        // optional, this is the default
   "info": ["seedance_2_5 · 720p · 4 s · audio on", "job 93f6390d · 2K 1440×2560"]
 },
 "count_note": "optional extra words on the Prompts bar",
 "det": [ ... ]                       // §2.5, the Prompts drawer
}
```

Computed by the builder:

| thing | rule |
|---|---|
| `data-shot` | `v<n>_<clip>` — the id in Daniel's decision lines |
| `data-file` | `file` if given (it must be one of the card's own file names); else stage `clip` → the take's file name, stage `frame` → the first frame's, stage `refs` → the first look's (`vN_cNN_r2.png`, the new person) |
| `data-driver` | the `driver` path, on motion-transfer cards only - it is how `extract_board.py` gets the driver back |
| status chip | `FRAME FOR REVIEW` / `FRAME APPROVED` / `FRAME REJECTED` / `CLIP FOR REVIEW` / `APPROVED` / `REJECTED`, then ` · gN` from `data-file`; stage `refs`: `REFS FOR REVIEW` / `REFS APPROVED` / `REFS REJECTED` |
| stage `refs` | a motion-transfer run before anything is generated: needs `driver` and `looks`, no `take`, no `frames`. Daniel approves the pictures (`APPROVE vN_cNN_r2.png`), then the clip is made (`add_card.py --clip --driver` refuses while the refs are not approved) and the card becomes stage `clip`, keeping its `looks` |
| card width | 372 px; 724 px (`.card.two`) with two frames. Frame column always 342 px |
| empty clip area | stage `frame`: a striped tile "Clip comes after this frame is approved" (or approved / rejected wording) |
| motion-transfer card | `driver` set, `frames` empty (every board, since 2026-09-25): a normal one-column card. Where a generated start frame normally sits, it plays **our generated clip** (the take's `play`, else its `file`), labelled `GENERATED CLIP · vN_cNN_gK.mp4`; the same clip also plays in the clip strip underneath, as on every clip card. **The driving (reference) video is never shown on the card** — it is listed only in the Prompts drawer's attachments (`video ref 1`). The build refuses `driver` together with frames or on stage `frame` |
| Approve / Reject | shown only when `status` is `review` |
| lost media | a file that does not exist but whose **file name** (not path) is listed in `content/lost_takes.txt` is drawn greyed "take lost"; a missing file that is not listed stops the build |

### 2.5 The Prompts drawer (`det`), in this order

1. For each frame: `head` → `refs` → `prompt` (image) → `split`
2. `head` "CLIP — file" while the video is in production ("CLIP IN THE CUT — file"
   once it is in the export) → `refs` (`vid: true`) → `prompt` (clip)
3. `alts` — every other take of the shot on disk
4. `notes` — what was learned in the round, verbatim
5. `arch` — the pointer to the shot in `prompts.md` (`§ CNN` while in production,
   `§ Verified record · CNN` once the video is exported and verified)

Block kinds:

```json
{"k": "head",   "text": "START FRAME — v17_c03_g2.png"}
{"k": "refs",   "vid": false, "title": "Attached, in this order",
                "items": [{"n": "@Image 1", "file": "references/ref01.png",
                           "note_html": "framing only &middot; <i>media 95c37a95</i>"}]}
{"k": "prompt", "label": "Image prompt · v17_c03_g2.png",
                "meta": "gpt_image_2_5 · sunburst · 9:16 · 2k · medium · 1520×2688 · job a6edcc8a",
                "text": "…the exact Higgsfield text…"}
{"k": "split"}
{"k": "alts",   "rows": [{"media": "content/video_17_assets/clips/v17_c03_g2.mp4",
                          "why_html": "job 0c1d2e3f &mdash; hands too big (Daniel)"}]}
{"k": "notes",  "html": "<div class=\"learn\"><span class=\"r-lbl\">Read</span><p>…</p></div>"}
{"k": "learn",  "title": "Check", "html": "<p>…</p>"}
{"k": "arch",   "html": "Every take … <code>content/video_17_assets/prompts.md</code> &sect; Verified record &middot; C03"}
{"k": "html",   "html": "anything else (avoid)"}
```

Rules for prompt blocks:

- `text` is **the exact prompt stored on the Higgsfield job** that made the file
  named in the label — byte for byte, never tidied or shortened.
- `meta` is the job's settings in this order: model · (gpt_image_2_5: its
  style) · aspect · resolution · quality · width×height · job <first 8 of id>
  for images; model · resolution · duration · aspect · audio · job for clips.
- Refs are listed in submission order: images `@Image 1..n`; clips
  `start frame`, `image ref n`, `video ref n`. Name the local file when it is
  on the drive — a take of this video by its bare file name (`v17_c03_g2.png`),
  anything else by its path from the product folder
  (`product_images/box_g1.png`); otherwise say it is not on the drive. Keep
  `<i>media xxxxxxxx</i>` (first 8 characters of the Higgsfield media id) in the note:
  `add_card.py` uses it to remember the names.
- A prompt that matches no Higgsfield job is shown only with
  `meta: "text from the old board · no matching Higgsfield job found"`.

The Prompts bar counts prompts and other takes by itself.

### 2.6 The columns layout (`"layout": "columns"`)

For a product made by remaking reels with motion transfer (Swanlift posture bra, since 2026-10-05: Daniel
wanted to see each reference next to its new woman and room, and later its result, to review faster).
Same data, same tools, same review lines — only the page is drawn differently:

```
            | Video 1 (heading spans its runs) | Video 2 | ...       one column per run (= one card,
1 Reference | C01 reel      | C02 reel         | C01     |           one motion-transfer generation),
2 New look  | woman · room  | woman · room     | ...     |           videos left to right, oldest first
3 Final     | our clip, or the export (spans)  | ...     |
  Prompts   | drawer        | drawer           | ...     |
```

- Every card needs a `driver`. Row 1 plays it (the reference reel), row 2 shows the card's `looks`
  and, at stage `refs`, the chip and Approve / Reject. Row 3 shows the lane's `final` export across
  the video's runs once it exists, else each run's generated clip (chip, Approve / Reject and
  **▶ Side by side**, which plays the reference muted next to our clip, in step), else a tile saying
  what the run waits for. The last row is the card's Prompts drawer (`tags` + `det`, as on a card).
- The video heading shows `n`, `title`, `source` (account · views · length · Open reel), `caption`
  (the reference's on-screen text) and `meta` (any rows; Shots is not added).
- The rows are one CSS grid (`.cgrid`, label column 168 px, run columns 324 px), so they line up by
  construction. Runs of one video sit 18 px apart; between two videos the gap is 18 + 64 px (`--vgap`, widened from 24 px on 2026-10-05 at Daniel's request):
  the first column of every video but the first is 24 px wider and its cells carry `data-vs`
  (margin-left), so the cells stay 324 px (Daniel, 2026-10-05: more space between the videos). The review element is the cell that carries `data-shot` / `data-status` / `data-file`.
- The page embeds its own `board_data.json` (`<script type="application/json" id="board-data">`), so
  `extract_board.py` reads a columns board back exactly. `check_board.py` checks that every run has
  its four cells.

## 3. The page

Top to bottom: title (brand, summary, legend, controls line) → panels → lanes,
oldest video first. Outside the canvas: the notes panel (left, vertically
centred, fixed while panning, resizable from its corner, folds from its title),
the controls bar (bottom right: Latest · Fit all · Review N · Copy decisions ·
Dark/Light — zoom is the mouse wheel / pinch, home is key `1`), the lightbox, the toast.
On a touch screen one finger pans and two fingers pinch-zoom the board (`#vp` has
`touch-action: none`, so the page itself never zooms). Under 700 px wide the notes
panel sits at the bottom, folded by default, and the controls bar wraps.

Keys: `0` fit all · `1` home (columns layout: the grid's rows at the left edge) · `2` newest video · `E` open/close every card (columns: every Prompts drawer) ·
`+`/`-` zoom · `D` dark / light (every board; remembered per board in `vb.theme.<key>`) · `Esc` close. Keys are ignored while typing in the notes.

Browser storage (per viewer, per board `key`):
`vb.notes.<key>` (+ `.t` time, `.open`, `.size`), `vb.review.<key>` (the
Approve/Reject decisions), IndexedDB `vb-notes` / store `h` (the connected
`board_notes.txt` file handle).

Notes sync with `board_notes.txt`: typing autosaves to the browser at once and
to the file within 0.4 s. On connect/reconnect, if both copies changed, both are
kept (joined under "— also typed in this browser —"). Text is never dropped.
Every read and write of the file goes through one queue, so a reconnect merge
always finishes before the next autosave and two saves never overlap.

Review: Approve copies `APPROVE <data-file>`, Reject asks for a reason and
copies `REJECT <data-file> — <reason>` (Cancel in that dialog records nothing).
Clicking the same button again clears it. Review N filters the canvas to the waiting cards. Copy decisions copies all
lines. Decisions left on cards that are no longer `review` are dropped on load.

Performance rules baked into `board.js`: one render loop, no layout reads while
moving, cards (and columns-layout cells) locked to measured sizes then culled with `content-visibility`,
videos are click-to-play facades (at most one `<video>` alive; two during Side by side), images lazy.
A press on a picture that does not turn into a drag opens it full size (handled on pointer-up: with the
pointer captured for panning, Chrome sends the click to `#vp`, not to the picture).

## 4. Design constants (do not drift)

Card 372 px / two-frame card 724 px / frame column 342 px / lane side 236 px.
Columns layout: label column 168 px / run column 324 px / gaps 14 px (rows) and 16 px (columns).
Group colours: Hook `#E8452C`, B-roll 1 `#2D6BF0`, B-roll 2 `#1F9D6B` (the
MerryGlow projector uses `#4D8DFF` and `#A16BC5` for its Product and Christmas
reveal groups). Chip colours: review `#c2410c`, approved `#1d4ed8`, rejected
`#9f1239`. Everything else is in `template/board.css`.

## 5. Changing the template

1. Edit `template/board.css`, `board.js` or `page.html`. After any colour change in
   the light rules of `board.css`, run `tools/make_dark_css.py`: it regenerates the
   dark theme block at the end of the file (never edit that block by hand; finishing
   touches go in the tool's `EXTRA`). The Hooks board (`x_systems/hooks/hooks_board.html`)
   has its own dark block: `make_dark_css.py --page x_systems/hooks/hooks_board.html`; its
   hand-tuned dark rules sit in its CSS just above the generated block.
2. `python3 x_systems/video_boards/tools/build_board.py` (no argument = every product).
3. `python3 x_systems/video_boards/tools/build_board.py --example`.
4. Run the checks (WORKFLOWS.md §7); open each board and try: pan, zoom, key 1,
   Latest, Dark/Light, E, a clip, a frame, Copy on a prompt, the notes.

Placeholders in `page.html`: `{{TITLE}} {{FAVICON}} {{THEME_HEAD}} {{CSS}} {{KEY}}
{{HEADER}} {{PANELS}} {{LANES}} {{THEME_BTN}} {{JS}}`. `board.js` expects these ids: `vp world zoom
zlast zfit zreview zcopy ztheme lb toast nb nblink`. Every board gets the dark /
light switch (`THEME_HEAD` applies the saved choice before the first paint).

## 6. Guarantees the builder enforces

It refuses to write the board (exit 1, old board untouched) when: the schema or
product name is wrong, a card has an unknown field or a bad stage/status, a
shot id repeats inside a video, a prompt is empty, a card's `file` is not one of
its own files, a generated frame or clip (`g<K>`) has no prompt block named after
it and no "No image/clip prompt on record" note (a historical gap must be said,
not skipped), or a file the page would load is missing and not listed in
`lost_takes.txt`. It writes through a temporary `.building` file and reads it
back, because this drive's mount has truncated writes before; that file is
created exclusively, so two sessions can never write the same board at once.
`add_card.py` and `decide.py` also refuse to save `board_data.json` when it changed
since they read it - the second of two sessions editing one board is stopped, not
silently overwritten. One broken board never stops the other boards from building.
