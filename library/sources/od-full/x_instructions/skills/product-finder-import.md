# Product Finder import

The Product Finder (`x_systems/product_finder/`) is Daniel's research library of competitor
accounts: **one card per source account**, organised **category → product → variation →
accounts** (one tree; the Real UGC / Other split was removed on 2026-10-05), each card showing
that account's best video of the product it sells *now*. New accounts come from the WhatsApp
group (a private product-hunting group). This skill replaces the ChatGPT procedure used until 2026-10-04
(same rules, same data, permanent tools).

## Never

- Never open, read, search or quote `notes.txt`, `board_notes.txt`, `guides.txt`. On the board,
  never read the Notes textarea (`#nb textarea`) and collapse the Notes card before any screenshot.
- `keys.txt`: only the Apify keys, and only through the tool. Never print a key, never read the
  other sections.
- Never send anything in WhatsApp. Read only.
- Never hand-edit `product_board.html` or `links.txt` - both are generated by the tool.
- Never restore an account Daniel removed (the tool's `check` and `triage` know the removals).
- Never reverse Daniel's manual corrections (labels, removals) on existing accounts. The labels from
  the 2026-10-05 relabel are the approved baseline: if an import shows one is wrong, tell Daniel
  and change it only when he agrees.
- Never bring back content sections (`contentSections`, `contentSection`, `ugcReview`, `ugcPolicy`) -
  `check` fails on them.
- Never substitute an older viral video, another account's video, or a guessed number. Unknown
  is unknown, not zero; a real zero stays zero.
- Never touch `x_systems_shared/` (partner copies) unless Daniel asks.

The tool (run from the drive root on Daniel's computer, `device_bash`):

```
T=x_systems/video_boards/tools/product_finder.py
python3 $T triage FILE            # every link in FILE -> present / removed / new / needs_resolution
python3 $T apify-balance          # credit left on every Apify key
python3 $T apify-run ACTOR INPUT.json LABEL --max-usd 1 [--wait 150]   # best-fit key, evidence saved
python3 $T apify-fetch LABEL      # finish a run that outlived the 180 s shell limit
python3 $T all                    # rank + links + build + check (exit 0 or the job is not done)
python3 $T check                  # validate only
```

Writes on this drive: write to `/tmp`, `cp` onto the drive, `md5sum` both. The tool already does
this for its own files.

## 1. Before starting

1. `python3 $T check` must exit 0. If not, stop and tell Daniel what is wrong - do not import on
   top of a broken board.
2. Note the md5 of `board_data.json`; copy it to `/tmp/board_data_before.json` (recovery copy).
3. `python3 $T apify-balance` - make sure there is enough credit (≈ $0.003 per profile or reel).
4. Install yt-dlp if missing: `pip install --user -q yt-dlp` (run as `python3 -m yt_dlp`).

## 2. Collect the WhatsApp submissions (Chrome extension)

Read the `chrome-browser` skill first. Open `https://web.whatsapp.com` in a new tab in Daniel's
Chrome, open the product-hunting group. If WhatsApp shows a QR code, stop and ask Daniel to
log in.

- **Boundary:** the previous import is the newest `raw/research/update_*_review.json`
  (`checkedAt`, `submittedLinks`). Scroll back until you reach messages containing those last
  links, then go **one day further** (overlap is free: triage dedupes).
- Extract every instagram / tiktok / facebook link from the messages since the boundary, with the
  message date (and sender name only if needed to tell messages apart). Prefer reading the
  message DOM with `javascript_tool` over screenshots.
- Append the new links (one per line, as posted) to `raw/whatsapp_viral_products.txt`, and save
  the batch to `/tmp/new_links.txt`.

## 3. Triage and resolve

`python3 $T triage /tmp/new_links.txt` classifies every unique link:

- `present` - already a card (keeps its card and original batch; refresh only if Daniel asks).
- `removed <date>` - Daniel removed it. Skip and report. Never re-add.
- `new` - candidate account.
- `needs_resolution` - a shared reel/post/short link whose owner is unknown. Resolve with
  `apify~instagram-reel-scraper` input `{"username": [<reel urls>], "resultsLimit": 1}`
  (`ownerUsername`); TikTok/Facebook short links: open them in Chrome and read the account. Append
  every Instagram resolution to `raw/reel_owner_map.txt` as `CODE=handle` (`CODE=ERR` when it
  failed), then re-run triage. Anything still unresolved stays listed as unresolved for next time.

Dedupe by **account**, not by link: a profile and a reel from it are one account; several reels
from one account are one card; the same product from different accounts are separate cards; the
same brand on another platform is a separate source account. If an account looks renamed or two
identities conflict, investigate before creating a card.

## 4. Collect the data (Apify, labels `update_<mon><dd>_<what>`)

Write each input JSON to `/tmp`, then `apify-run`. Keep runs small (≤ 6 accounts, cap $1) so they
finish inside the shell limit; `apify-fetch` the rest.

- Profiles: `apify~instagram-profile-scraper` `{"usernames": [...]}` → `followersCount`,
  `postsCount`, `biography`, `externalUrl`, `fullName`, `private`.
- Histories: `apify~instagram-reel-scraper`
  `{"username": [...], "resultsLimit": 60, "skipPinnedPosts": false, "skipTrialReels": false}` →
  per reel `id`, `shortCode`, `url`, `timestamp`, `videoPlayCount` (exact views), `likesCount`,
  `commentsCount`, `caption`, `isPinned`, `videoDuration`, `videoUrl`. If 60 does not reach the
  start of the current product run, rerun that account with a higher limit.
- TikTok: `clockworks~tiktok-profile-scraper`; Facebook: `apify~facebook-pages-scraper` +
  `apify~facebook-reels-scraper` (as in earlier evidence; check the actor's input schema first).
- Private, empty or failed accounts: record them as unresolved with the reason. Never fill the gap
  from memory or another source.

Order every account's videos by `timestamp` (pinned posts are not automatically newest).

## 5. Find the latest continuous product run (the central rule)

For each new account, decide what product it promotes **now** and where that run starts:

- Look at the footage, not the username, bio, caption, packaging text or first frame. Download the
  newest few videos and the ones around a suspected switch and make a 3x3 contact sheet of each
  (9 frames spread over the whole video), then stage and view the sheets:
  ```
  d=$(ffprobe -v error -show_entries format=duration -of csv=p=0 V.mp4)
  ffmpeg -v error -y -i V.mp4 -vf "fps=9/$d,scale=300:-2,tile=3x3" -frames:v 1 V_sheet.jpg
  ```
- The run is the newest unbroken sequence of videos showing the same underlying product. Cosmetic
  designs, fandoms, colours and seasonal themes are variations of one product. A comparison object
  or a hook at the start is not a product switch - watch the rest.
- Product A → B → A again: only the latest A run counts.
- Record `latestRun`: `status` (`current`, or `review` when the latest product stays mixed or
  ambiguous), `product`, `checkedAt`, `boundaryStatus` (`no_switch_identified` /
  `switch_identified` / `uncertain`), `videoIds` (newest first), `observedCount`,
  `olderBoundaryId` (newest video of the previous product, or null), `selection`
  (`highest_observed_views`), `coverage` (what was and was not seen, in one or two sentences).
- `review` accounts get an honestly labelled latest preview and are **not ranked**
  (`performance.eligible: false`, `excludedReason: "Mixed or ambiguous recent products"`).

## 6. Label and place

Print the current tree and the tags already in use before labelling anything:

```
python3 -c "
import json,collections
D=json.load(open('x_systems/product_finder/board_data.json',encoding='utf-8'))
b={x['id']:x['title'] for x in D['branches']}
for p in D['products']:
    print(b[p['branch']],'>',p['title']); [print('   ',v['title'],v['accounts']) for v in p['variations']]
print(collections.Counter(t for a in D['accounts'] for t in a['niches']))
print(collections.Counter(t for a in D['accounts'] for t in a['occasions']))"
```

- Label the actual product from the footage, specific enough to tell products apart (heated robe ≠
  robe, posture bra ≠ back brace, pickleball paddle ≠ tennis racket, sphere room-scene projector ≠
  mini video projector), no promotional slogans, no functional claims without evidence. The
  account name, bio and store link do not decide the product.
- **Same physical product = same product and same variation**, whatever the account name, the
  footage style or the angle. Before placing a new account, compare its frames side by side with
  the accounts already in the closest products (a contact sheet of ~9 frames per video) - this is
  how @thevareny / @backalign.official / @marlein.co (one posture bra) were found filed in two
  categories.
- A product node is one product format; its variations are designs, fandoms, niches or seasons
  (e.g. Advent calendars → `Die-cast cars · Hot Wheels`). When one node holds different items,
  name variations `<item> · <design>` so two variations never describe the same thing.
- Reuse an existing product and variation when it fits; create a product only for a genuinely
  distinct product format, in the right category (`branches`: Lighting & atmosphere, Clothing &
  comfort, Health & beauty, Pets & family, Gifts & play, Sport & outdoors, Home & everyday, Car
  accessories). `variant`, `treeVariant` and `latestRun.product` all equal the variation title.
- Tags: `niches` (audience / fandom, e.g. Golf, Harry Potter, Parents) and `occasions`
  (Christmas, Halloween, Winter) from the footage and captions; [] when none. Reuse the exact
  spellings already on the board (printed above) - a new tag only for a genuinely new audience.
- Mistakes the 2026-10-05 relabel had to fix - check each new label against them:
  - wrong mechanism: a stencil duster called a printer, a magnetic disc player called vinyl, a
    water-mist projector called a hologram, a mini video projector called a scene projector;
  - wrong form: briefs called a wrap, a lift-up top called a drawer, a rider costume called a
    ride-on toy, an unheated robe filed with heated ones;
  - one product split over two variations with near-identical names ("Tennis calendar" /
    "Tennis advent calendar"), or two different items sharing one variation (two different
    rhinestone hoodies, a Porsche sled and a BMW sled);
  - the product only half-shown (only the remote, or the box): say so in `coverage` and label
    only what the footage supports.
- When the bio, store link or caption sells something else than the footage shows, the footage
  decides; record the mismatch in `note` (e.g. "Bio and store sell a retro phone handset; the
  latest run shows the Trump toilet brush.") and list it in the report.
- Second opinion before writing: give a fresh subagent each new account's contact sheet next to
  the sheets of the accounts already in its proposed product (one montage per product, the
  variation written above every sheet) and ask it to find errors against the rules above. Look at
  every point it raises yourself before changing anything.

## 7. Featured video and metrics

- Featured video = **highest `videoPlayCount` inside the latest run** (not the WhatsApp reel, not
  an older viral). Keep its original URL and id. With Apify data, views are exact
  (`viewsApproximate: false`); rounded counts from a browser stay `true` and ties must be disclosed.
- `followers` = account-wide (may come from earlier products).
- Performance sample = the newest **up to 20** videos of the run: `videoIds`, `sampleCount`,
  `averageViews` = arithmetic mean, `smallSample` = fewer than 20. Never pad with an earlier
  product. Eligible only with verified followers, a `current` run and ≥ 1 sampled video.
- Keep post totals (`posts`), observed videos (`fetchedVideos`/`videoCount`) and run counts apart.
- Leave `score` and `rank` to the tool.

## 8. Media

For every featured video:

```
python3 -m yt_dlp -q -o "$HOME/pf/<prefix>_<handle_with_dots_as_underscores>_<videoId>.%(ext)s" <url>
ffprobe ...   # duration ≈ videoDuration, a video stream decodes, an audio stream exists (or record none)
ffmpeg -ss 1 -i <mp4> -frames:v 1 -vf scale=360:-2 -q:v 3 <same name>.jpg
```

Name: `ig_`/`tt_`/`fb_` + handle (dots → underscores) + `_` + video id, `.mp4` + `.jpg`. Never
overwrite an existing file; never trim; keep the original audio. View the thumbnail - it must show
the labelled product. `cp` into `media/`, md5 both. If a video cannot be downloaded, set no
`media`, set `availability` and say so.

## 9. Update the data

Work on a copy, write with the md5 lost-update guard (the file must still match the md5 from step 1).

- **New account record:** copy the full field set of the most recently added account of the same
  platform and fill every field from the evidence (`key` = `ig:<handle>` / `tt:<handle>` /
  `fb:<page id>`, `sourceUrl`, profile fields, `family`/`treeProduct`/`originalFamily`,
  `familyTitle`/`treeProductTitle`, `variant`/`treeVariant`, `branch`, `group`, `niches`,
  `occasions`, `note`, `video`, `media`/`poster`/`duration`/`audioTracks`, `latestRun`,
  `performance`, `identification` (`"Video reviewed"`), `coverage`, `coverageNote`,
  `evidence`/`mediaEvidence` = the review file, `checkedAt`/`productCheckedAt`/`metricsCheckedAt`
  = today).
- Add the key to its product's variation in `products` (new variation or family when needed;
  `families` gets the matching entry).
- **Batch** (only if at least one account was actually added): next number, `id: batch-N`,
  `addedAt` = today in Europe/Chisinau (`YYYY-MM-DD`), `accountKeys` in submission order. Existing
  accounts keep their batch. Several imports on one day get several batches.
- `audit.latestImport` and `audit.updateCheckedAt` describe this import (submitted links, new
  accounts, repeated accounts, resolved reels, unresolved, evidence file). Keep older audit
  entries and dates.
- Write `raw/research/update_<mon><dd>_review.json` (same shape as the previous one):
  `checkedAt`, `submittedLinks`, `addedAccounts`, `alreadyPresent`, `removedEncountered`,
  `sharedReelResolution` (`{code: handle}`), `unresolved` (link + reason), `newAccounts` (profile,
  ordered history, run boundary, featured choice, sample, labels per account),
  `collection` (method), `previousAccountKeys`, `validation`.
- If Daniel removes an account later: drop it from the account list, products and its batch (the
  batch keeps its date), append `{key, removedAt, request}` to `raw/research/removals.json`.

Then `python3 $T all` - it recomputes rankings, the worst 50 and counts, rewrites `links.txt`,
rebuilds the board and runs every data check. Exit 0 or the job is not done.

## 10. Verify in a browser

Open the board (`file:///<path-to-this-drive>/x_systems/product_finder/product_board.html`)
in Chrome - the extension needs "Allow access to file URLs" switched on; the built-in browser
cannot open file:// pages. If neither works, stage the board and its media and check it in a
headless Chromium in the workspace (that Chromium cannot play H.264, so playback stays
unverified - say so). Collapse Notes first. For **every new card**: search (`#search`) finds it;
label, category, batch and thumbnail are right; opening it plays the right account's video with
sound and seeking works. The new batch in `#batch-select` highlights exactly its members;
`#batch-prev`/`#batch-next` visit each member once; "All batches" restores the view; pan/zoom
works; no console errors. Prefer `javascript_tool` checks; a data check or a successful download
is not proof the board works.

## 11. Report to Daniel

Short: batch number + date, accounts added (handle → product → variation), already present,
removed accounts encountered, unresolved links / unavailable videos / accounts left in review,
labels with low confidence and accounts whose bio or store contradicts the footage,
Apify credit used and left, checks run with exit codes and what could not be verified. Never say
"verified" for a step that was skipped or blocked.
